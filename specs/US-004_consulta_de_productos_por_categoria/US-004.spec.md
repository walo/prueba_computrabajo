## 1. Contratos de Datos y API (Interface Definition)

Siguiendo la **Regla 7 de Redarbor** (*pasar Objetos y no Propiedades como parámetros*), los filtros de entrada y la consulta de aplicación se encapsulan en objetos fuertemente tipados. Cada `record` o `interface` reside en su propio archivo físico (Regla 6).

### A. DTOs / ValueObjects de Entrada (Request & Filter Models)

Referencia tipada para consumidores HTTP/TypeScript:

```typescript
export interface CategoryProductsFilter {
  page: number;
  pageSize: number;
  search?: string;
  isActive?: boolean | null;
  lowStockOnly?: boolean | null;
}
```

Contratos en C# (`Domain.ValueObjects` y `Application.Features.Products.Queries.GetProductsByCategory`):

```csharp
    Guid CategoryId,
```

### C. Endpoints HTTP (RESTful RFC 7807 & PBAC)

| Método | Ruta | Permiso Requerido (PBAC) | Éxito | Errores Posibles |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/categories/{categoryId:guid}/products` | `[HasPermission(Permissions.ProductsRead)]` | `200 OK` (`PagedProductsResponse`) | `400 BadRequest` (`ValidationProblemDetails`), `401 Unauthorized`, `403 Forbidden`, `404 NotFound` (`Category.NotFound`) |

#### Parámetros de Consulta (`[FromQuery] CategoryProductsFilter`)

| Parámetro | Tipo | Requerido | Valor por Defecto | Regla de Validación |
| :--- | :--- | :--- | :--- | :--- |
| `page` | `int` | No | `1` | Entero `>= 1` |
| `pageSize` | `int` | No | `10` | Entero inclusivo entre `1` y `100` |
| `search` | `string?` | No | `null` | Longitud máxima `150` caracteres (busca por `Sku` o `Name` sin distinguir mayúsculas/minúsculas) |
| `isActive` | `bool?` | No | `null` | Filtra por estado operativo del producto (`true`, `false` o todos si es `null`) |
| `lowStockOnly` | `bool?` | No | `null` | Si es `true`, retorna solo productos con `Stock <= MinStock` |

## 2. Diseño de Backend (.NET 10 Onion Architecture & SQL Server 2022)

- **Reglas de Clean Code Redarbor Obligatorias (`.agents/rules/redarbor-clean-code.md`):**
  - [ ] Código, identificadores, pruebas y comentarios 100% en inglés (mensajes de dominio devueltos al cliente en español).
  - [ ] Cero líneas en blanco internas en métodos o funciones, excepto una única línea inmediatamente antes de `return`.
  - [ ] Nombres autodescriptivos sin comentarios explicativos dentro de métodos (`0` comentarios innecesarios).
  - [ ] Máximo `25` líneas por método y máximo `1` nivel de anidamiento de bucles/condicionales.
  - [ ] Configuración gobernada por variables de entorno / `IConfiguration` (sin valores quemados).
  - [ ] Exactamente `1` tipo público (`class` / `record` / `interface` / `enum`) por archivo `.cs`.
  - [ ] Pasar objetos cohesivos (`CategoryProductsFilter`, `CategoryProductsQuery`) en lugar de múltiples propiedades escalares.

### B. Aplicación (`src/backend/src/Core/Application`)
- **Interfaces (`Common/Interfaces/`):**
  - Actualizar `ICategoryFinder.cs` agregando:
    ```csharp
    Task<bool> ExistsAsync(Guid id, CancellationToken ct = default);
    ```
  - Reutilizar `IProductFinder.cs` (`Task<PagedProductsResponse> GetPagedAsync(ProductFilter filter, CancellationToken ct = default);`).
- **Nuevo Vertical Slice `Features/Products/Queries/GetProductsByCategory/`:**
  - `GetProductsByCategoryQuery.cs`: `public sealed record GetProductsByCategoryQuery(CategoryProductsQuery Request) : IRequest<ErrorOr<PagedProductsResponse>>;`
  - `GetProductsByCategoryQueryValidator.cs` (`AbstractValidator<GetProductsByCategoryQuery>`):
    - Valida `RuleFor(x => x.Request).NotNull();` y delega a helper privado `ConfigureRequestRules()` con `When(x => x.Request is not null, ConfigureRequestRules)`.
    - `ConfigureRequestRules()`: valida `RuleFor(x => x.Request.CategoryId).NotEmpty();`, `RuleFor(x => x.Request.Filter).NotNull();` y `When(x => x.Request.Filter is not null, ConfigureFilterRules)`.
    - `ConfigureFilterRules()`: valida `Page >= 1`, `PageSize` entre `1` y `100`, y `Search` con longitud máxima `150`.
  - `GetProductsByCategoryQueryHandler.cs` (`ICategoryFinder categoryFinder, IProductFinder productFinder`):
    - **Onion estricto:** Inyecta únicamente `ICategoryFinder` e `IProductFinder`; jamás inyecta `AppDbContext` ni `IRepository`.
    - Flujo `Handle(GetProductsByCategoryQuery query, CancellationToken ct)`:
      1. Verifica `var categoryExists = await categoryFinder.ExistsAsync(query.Request.CategoryId, ct);`.
      2. Si `!categoryExists`, retorna `Error.NotFound("Category.NotFound", "La categoría solicitada no existe.");` (`404 Not Found`).
      3. Construye `ProductFilter` mediante el helper privado `BuildProductFilter(query.Request)` forzando `CategoryId = request.CategoryId` y delega a `await productFinder.GetPagedAsync(filter, ct)`.
      4. Si la categoría existe (esté *Activa* o *Inactiva*) y no tiene productos coincidentes, retorna `200 OK` con `Items` vacío y `TotalCount = 0`.

    ```csharp
    [HttpGet("{categoryId:guid}/products")]
    [HasPermission(Permissions.ProductsRead)]
    [ProducesResponseType(typeof(PagedProductsResponse), StatusCodes.Status200OK)]
    [ProducesResponseType(typeof(ValidationProblemDetails), StatusCodes.Status400BadRequest)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status401Unauthorized)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status403Forbidden)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status404NotFound)]
    public async Task<IActionResult> GetProductsByCategory(
        Guid categoryId,
        [FromQuery] CategoryProductsFilter filter,
        CancellationToken ct)
    {
        var request = new CategoryProductsQuery(categoryId, filter);
        var result = await sender.Send(new GetProductsByCategoryQuery(request), ct);

        return result.Match(Ok, HandleFailure);
    }
    ```
