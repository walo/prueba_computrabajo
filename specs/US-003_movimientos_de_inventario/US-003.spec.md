## 1. Contratos de Datos y API (Interface Definition)

Siguiendo la **Regla 7 de Redarbor** (*pasar Objetos y no Propiedades como parámetros*), todos los comandos, consultas, métodos de dominio y servicios reciben objetos fuertemente tipados. Cada clase, `record` o `interface` reside en su propio archivo físico (Regla 6).

### C. Endpoints HTTP (RESTful RFC 7807 & PBAC)
| Método | Ruta | Permiso Requerido (PBAC) | Éxito | Errores Posibles |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/inventory-movements` | `[HasPermission(Permissions.InventoryMovements.Read)]` | `200 OK` (`PagedInventoryMovementsResponse`) | `400 BadRequest`, `401 Unauthorized`, `403 Forbidden` |
| `GET` | `/api/v1/inventory-movements/{id:guid}` | `[HasPermission(Permissions.InventoryMovements.Read)]` | `200 OK` (`InventoryMovementResponse`) | `401 Unauthorized`, `403 Forbidden`, `404 NotFound` |
| `POST` | `/api/v1/inventory-movements` | `[HasPermission(Permissions.InventoryMovements.Create)]` | `201 Created` (`InventoryMovementResponse` + `Location`) | `400 BadRequest`, `401 Unauthorized`, `403 Forbidden`, `404 NotFound`, `409 Conflict` |

> **Nota de Inmutabilidad:** No se exponen endpoints `PUT`, `PATCH` ni `DELETE` en `/api/v1/inventory-movements`. El Kardex es estrictamente append-only; las correcciones operativas se realizan mediante nuevos movimientos compensatorios.

## 2. Diseño de Backend (.NET 10 Onion Architecture & SQL Server 2022)

- **Reglas de Clean Code Redarbor Obligatorias:**
  - Código y comentarios 100% en inglés (mensajes devueltos al usuario final en español cuando aplique).
  - Cero líneas en blanco dentro de métodos/funciones excepto 1 línea antes de `return`.
  - Métodos de máximo `25` líneas y máximo `1` nivel de anidación de ciclos/condicionales.
  - Exactamente 1 tipo público (`class` / `record` / `interface` / `type`) por archivo `.cs`.
  - Pasar objetos (`InventoryMovementCreationData`, `InventoryMovementFilter`) en lugar de listas de propiedades escalares.

### A. Dominio (`src/backend/src/Core/Domain`)
- **Constantes de Tipo (`Constants/InventoryMovementTypes.cs`):**
  - `Entry = "ENTRY"`, `Exit = "EXIT"`.
  - `Normalize(string? value)` retorna `(value ?? string.Empty).Trim().ToUpperInvariant()`.
  - `IsValid(string? normalizedValue)` valida `normalizedValue is Entry or Exit`.
- **Entidad `InventoryMovement : AggregateRoot<Guid>` (`Entities/InventoryMovement.cs`):**
  - Propiedades (solo `private set`, inmutable después de `Create`):
    - `Id` (`Guid`)
    - `ProductId` (`Guid`, referencia lógica a `Product` sin `FOREIGN KEY`)
    - `Type` (`string`, `"ENTRY"` o `"EXIT"`, `nvarchar(10)`)
    - `Quantity` (`int`, `>= 1`)
    - `PreviousStock` (`int`, `>= 0`)
    - `NewStock` (`int`, `>= 0`, calculado automáticamente)
    - `Reason` (`string`, requerido, `Trim()`, longitud `3`–`300`)
    - `PerformedByUserId` (`Guid`, requerido, resuelto desde JWT)
    - `CreatedAtUtc` (`DateTime`)
  - Método de fábrica:
    - `public static ErrorOr<InventoryMovement> Create(InventoryMovementCreationData data)`
    - Valida `ProductId != Guid.Empty`, `PerformedByUserId != Guid.Empty`, `PreviousStock >= 0`, `InventoryMovementTypes.IsValid(normalizedType)`, `Quantity >= 1`, `Reason` con longitud `3`–`300`.
    - Calcula `newStock = normalizedType == InventoryMovementTypes.Entry ? data.PreviousStock + data.Quantity : data.PreviousStock - data.Quantity`.
    - Si `newStock < 0`, retorna `Error.Conflict("InventoryMovement.InsufficientStock", "El stock disponible es insuficiente para realizar la salida solicitada.")`.
    - Emite `InventoryMovementCreatedDomainEvent`.
- **ValueObjects / Parameter Objects (`ValueObjects/`):**
  - `InventoryMovementCreationData.cs`: `public sealed record InventoryMovementCreationData(Guid ProductId, string Type, int Quantity, int PreviousStock, string Reason, Guid PerformedByUserId);`
  - `InventoryMovementFilter.cs`: `public sealed record InventoryMovementFilter(int Page = 1, int PageSize = 10, string? Search = null, Guid? ProductId = null, string? Type = null, DateTime? FromDateUtc = null, DateTime? ToDateUtc = null);`
- **Eventos de Dominio (`Events/`):**
  - `InventoryMovementCreatedDomainEvent.cs`
- **Permisos PBAC (`Constants/Permissions.cs`):**
  - Verificar permanencia de `Permissions.InventoryMovements.{Read, Create}` ya registrados en `Permissions.GetAll()` y sembrados en `InitialDataSeeder.cs` (`ADMIN` ambos; `USER` solo `InventoryMovements.Read`).

### B. Aplicación (`src/backend/src/Core/Application`)
- **Interfaces (`Common/Interfaces/`):**
  - `IInventoryMovementRepository.cs`:
    - `Task AddAsync(InventoryMovement movement, CancellationToken ct = default);`
  - `IInventoryMovementFinder.cs`:
    - `Task<PagedInventoryMovementsResponse> GetPagedAsync(InventoryMovementFilter filter, CancellationToken ct = default);`
    - `Task<InventoryMovementResponse?> GetByIdAsync(Guid id, CancellationToken ct = default);`
- **Feature Slice `Features/InventoryMovements/`:**
  - `Commands/CreateInventoryMovement/`:
    - `CreateInventoryMovementCommand.cs`
    - `CreateInventoryMovementCommandValidator.cs`: usa `RuleFor(x => x.Request).NotNull();` y guarda `When(x => x.Request is not null, ...)` validando `ProductId` no vacío, `Type` (`ENTRY`/`EXIT` case-insensitive), `Quantity >= 1` y `Reason` no vacío entre `3` y `300` caracteres.
    - `CreateInventoryMovementCommandHandler.cs`: inyecta `IInventoryMovementRepository`, `IProductRepository`, `IUserRepository`, `ICurrentUserContext`, `IUnitOfWork` (nunca `AppDbContext`):
      1. Verifica `currentUserContext.UserId` (`401 InventoryMovement.UnauthorizedUser` si es `null`).
      2. Busca `Product` vía `productRepository.GetByIdAsync(request.ProductId, ct)` (`404 InventoryMovement.ProductNotFound` si es `null`).
      3. Verifica `product.IsActive` (`409 InventoryMovement.ProductInactive` si es `false`).
      4. Construye `InventoryMovement.Create(new InventoryMovementCreationData(...))`.
      5. Ajusta stock con `product.AdjustStock(movement.NewStock)`.
      6. Persiste movimiento (`inventoryMovementRepository.AddAsync`) y producto actualizado (`productRepository.UpdateAsync`) + `unitOfWork.SaveChangesAsync(ct)`.
      7. Resuelve `PerformedByEmail` (`currentUserContext.Email` o fallback vía `userRepository.GetByIdAsync`) y retorna `InventoryMovementResponse`.
  - `Queries/GetInventoryMovements/`:
    - `GetInventoryMovementsQuery.cs`
    - `GetInventoryMovementsQueryValidator.cs`: usa `RuleFor(x => x.Filter).NotNull();` y guarda `When(x => x.Filter is not null, ...)` validando `Page >= 1`, `PageSize` entre `1` y `100`, `Type` válido si se envía (`null`/vacío o `ENTRY`/`EXIT`), y `FromDateUtc <= ToDateUtc` cuando ambas fechas están presentes.
    - `GetInventoryMovementsQueryHandler.cs`: delega en `IInventoryMovementFinder.GetPagedAsync(query.Filter, ct)`.
  - `Queries/GetInventoryMovementById/`:
    - `GetInventoryMovementByIdQuery.cs`, `GetInventoryMovementByIdQueryValidator.cs`, `GetInventoryMovementByIdQueryHandler.cs` (`404 InventoryMovement.NotFound` si no existe).
  - `DTOs/` (`CreateInventoryMovementRequest.cs`, `InventoryMovementResponse.cs`, `PagedInventoryMovementsResponse.cs`).

### C. Infraestructura y Persistencia SQL Server (`src/backend/src/Infrastructure/Persistence`)
- **`AppDbContext.cs`:** `public DbSet<InventoryMovement> InventoryMovements => Set<InventoryMovement>();`
- **`Configurations/InventoryMovementConfiguration.cs`:**
  - Tabla: `InventoryMovements`, clave primaria `Id` con `.ValueGeneratedNever()`.
  - Columnas: `ProductId` (`uniqueidentifier` required), `Type` (`nvarchar(10)` required), `Quantity` (`int` required), `PreviousStock` (`int` required), `NewStock` (`int` required), `Reason` (`nvarchar(300)` required), `PerformedByUserId` (`uniqueidentifier` required), `CreatedAtUtc` (`datetime2` required).
  - Índices: `IX_InventoryMovements_ProductId`, `IX_InventoryMovements_CreatedAtUtc` (no únicos).
  - **Prohibido usar `.HasForeignKey()` o `FOREIGN KEY`**.
- **`Finders/InventoryMovementFinder.cs`:**
  - Lectura 100% con **EF Core `.AsNoTracking()`** y `GroupJoin` / `DefaultIfEmpty` lógico entre `InventoryMovements`, `Products` (`movement.ProductId == product.Id`) y `Users` (`movement.PerformedByUserId == user.Id`) para proyectar `ProductSku`, `ProductName` y `PerformedByEmail`.
  - Filtros soportados: `ProductId`, `Type` (normalizado `ENTRY`/`EXIT`), `FromDateUtc`, `ToDateUtc`, `Search` (sobre `ProductSku`, `ProductName` o `Reason`), ordenamiento `OrderByDescending(item => item.CreatedAtUtc)` y paginación `Skip`/`Take`.
- **`Repositories/InventoryMovementRepository.cs`:**
  - `INSERT INTO InventoryMovements (...)` parametrizado con **Dapper** usando `IDbConnectionFactory` en bases relacionales (con respaldo EF Core InMemory cuando `!dbContext.Database.IsRelational()`).
- **`Repositories/ProductRepository.cs` (Activación de respaldo InMemory):**
  - Mantener verificación relacional de 2 pasos (`OBJECT_ID`) y actualizar el retorno no relacional de `HasInventoryMovementsAsync` a `await dbContext.InventoryMovements.AsNoTracking().AnyAsync(movement => movement.ProductId == productId, ct)`.
- **Migración EF Core `AddInventoryMovements`:** Verifica `0` ocurrencias de `ForeignKey`.

### D. Presentación (`src/backend/src/Presentation/Web.API`)
- `Controllers/InventoryMovementsController.cs`: hereda `ApiController`, ruta `api/v1/inventory-movements`, decorado con `[HasPermission(Permissions.InventoryMovements.*)]`.
